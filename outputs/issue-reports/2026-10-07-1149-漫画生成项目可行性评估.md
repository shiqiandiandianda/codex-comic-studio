# PhotoCraft + Codex CLI 漫画生成项目可行性评估

## 1. 基本信息

- 初次评估：2026-10-07 11:49（Asia/Shanghai）。
- 最新修订：2026-10-07 12:53（Asia/Shanghai）。
- 状态：已解决（完成可行性评估与生图能力纠正；产品尚未实现）。
- 影响范围：漫画生产流程、编辑器选型、Codex CLI 接入、资产绑定、任务队列、人工 QA 和按话项目管理。
- 对象：PhotoCraft 当前主分支、当前本机 Codex CLI 0.160.1。

## 2. 任务概述与用户确定的流程

用户目标：分镜表格输入 → 表格、排版参考图、生成标准文档和资产图交给 Codex CLI → 返回排版参数与提示词 → 系统创建页面格子并绑定提示词 → 系统排队交给 Codex CLI 生图 → 图片嵌入对应格子 → 本话生成完成后自动后台制作下一话，同时人工 QA 已完成页面 → 就绪后导出。

最新约束：**排版规划和图片生成都通过 Codex CLI；不要求另接 ComfyUI、Stable Diffusion 或独立 Image API。**

预期交付是技术评估与可实施的接口边界；实际结果是确认该组合具备实现基础，并明确需要新增漫画业务数据、调度器和画布集成。本次没有开展产品编码或生成漫画图片。

## 3. 最终结论

整体可行。主架构采用：

- PhotoCraft：可编辑画布、图层、蒙版、文字、形状、渐变、变换与文档导出。
- 漫画业务系统：分镜导入、排版校验、资产绑定、提示词与格子关联、版本记录、任务排队、按话项目、QA 与导出状态。
- Codex CLI：通过两个任务类型完成排版规划与内置生图/编辑。
- CodexWorker：应用自己的 CLI 适配层，负责启动任务、读取事件、整理输出图片、归档结果和将结果绑定到正确话/页面/格子。

PhotoCraft 自身缺少生成式 AI，不妨碍该流程；生图由 Codex CLI 提供。前版将“CLI 帮助没有专用生图输出参数”推断成“必须另接外部生成器”，证据不足，本次撤回该结论。

| 目标 | 判断 | 需实现的部分 |
|---|---|---|
| 分镜到自动排版 | 中高 | 表格结构化、JSON Schema、几何与阅读顺序校验 |
| 框、气泡、拖图、渐变 | 高 | 漫画专用对象、气泡尾巴与检查器 |
| 使用 Codex CLI 生图 | 有能力基础 | CLI 生图任务、参考图传入、结果落盘接入与实际集成验证 |
| 边生成边人工编辑 | 中高 | 逐格完成即嵌入、候选版本、冲突检测 |
| 下一话后台制作、上一话 QA | 高 | 独立话项目、独立任务绑定、后台文档管理 |
| 全自动可出版质量 | 未验证 | 角色一致性、画面细节、文字、拼接与最终人工审校 |

## 4. 发现与可复核排查路径

### PhotoCraft

读取 README、AGENTS.md、架构、控制协议与路线图。已有图层组、像素/矢量蒙版、Shape/Text/Smart Object、渐变、变换、历史记录、PSD/PSB 和 .pcraft；UI、CLI、JSON 控制和 MCP 共用命令系统。

控制协议提供引擎命令执行、文档检查、保存、后台任务进度与取消。Smart Object 内容替换可以作为逐格回填候选图的基础。漫画 Panel、气泡、角色绑定及按话项目仍需要业务层。

PhotoCraft 官方明确处于 early alpha；复杂布局、长画布、中文排版和保存重开需要真实页面验收，不能从菜单命令数量推断专业可靠性。

### Codex CLI 生图能力纠正

1. 本地 `codex --version` 返回 `codex-cli 0.160.1`。
2. `codex exec --help` 支持 `-i/--image <FILE>...`、`--json` 和 `--output-schema`。
3. 本次实际运行 `codex features list | Select-String 'image_generation'`，返回：

```text
image_generation                         stable             true
```

4. 当前 CLI 二进制的只读检查找到 ImagegenArgs、image_gen.imagegen、image_generation_call、image_generation_begin/end 与 savedPath/saved_path 等符号。符号存在支持能力判断，但不能替代真实 JSONL 输出与文件回收测试。
5. 当前官方 [Image generation 文档](https://learn.chatgpt.com/docs/image-generation) 明确可在会话中使用 `$imagegen`，并通过 `-i/--image` 添加引导图片；同页说明多参考图需要按顺序标注用途。
6. 本地安装的 imagegen SKILL.md 明确内置 image_gen 为默认路径，支持生成、编辑与参考图。生成结果默认保存在 CODEX_HOME 下，项目资产需复制或移动到工作区；不能假设生图工具接受任意目标输出路径。

判断：CLI 没有独立 `generate-image` 子命令，不等于不能在代理任务中调用生图工具。用户要求统一使用 Codex CLI 成立，不再把外部生成器列为必需依赖。

## 5. 根本原因与确定性边界

- 已确认：本机 CLI 具有 image_generation 功能，当前为 stable true；官方文档提供 Codex 生图与参考图入口。
- 前版错误原因：将命令行 flag 列表当成代理全部工具能力，并把 OpenAI CLI API 示例当成唯一生图路径。
- 工程建议：以 CodexWorker 封装 CLI，而不是让产品直接解析自然语言来寻找图片。
- 尚未验证：当前账户在 `codex exec` 中实际完成生图、多参考图是否传入生图调用、JSONL 中具体事件字段、默认目录与最终落盘时机、并发数量、失败/取消恢复及与 PhotoCraft 的端到端回填。
- 本次没有用付费/额度生图测试来冒充上述验证完成。

## 6. 采用的处理方案与接口

保持用户完整链路，分为规划任务和生图任务；两类均由 Codex CLI 执行。

```text
输入：分镜表 + 排版参考图 + 标准文档 + 资产图
  ↓
Codex CLI 规划任务 → layout.json + 各格提示词 + asset_refs
  ↓
业务系统校验 → PhotoCraft 创建可编辑格子/气泡/文字/占位层
  ↓
任务队列 → Codex CLI 生图任务（提示词 + 本格参考资产 + 构图约束）
  ↓
生成图落盘 → CodexWorker 归档文件并规范化结果
  ↓
按 episode_id/page_id/panel_id 回填目标文档
  ↓
本话待 QA；后台创建下一话；人工修改/重生成
  ↓
QA 通过的文档修订 → 导出
```

保留生成后端抽象便于测试，但第一实现仅为 Codex CLI；不默认调用其他生图服务。

### 规划结果

建议布局结果带 `episode_id`、`page_id`、`panel_id`、`layout_revision`、坐标系/画布尺寸、格子几何、阅读顺序、气泡/文字参数、prompt、asset_refs 和构图安全区。

JSON Schema 只能验证结构；业务层仍须检查分镜覆盖、引用存在、边界、阅读顺序和气泡溢出。

### 生图任务

每次任务固定 `job_id`、目标 panel、prompt、实际参考图文件、参考用途、标准版本、输入修订号和输出目录。规划时查看过资产，不代表每次生图自动带上资产；生图任务必须显式传入本格相关图片并说明角色/服装/道具/场景/画风用途。

`-i` 让图片进入任务上下文；适配层还需核查实际生图调用是否使用指定引用。只给一个文件名或资产 ID 不等于已经给模型图像内容。

CodexWorker 建议整理如下结果契约（应用自定义，**不是已验证的 CLI 原始响应 schema**）：

```json
{
  "job_id": "j001",
  "episode_id": "ep-001",
  "page_id": "page-001",
  "panel_id": "p001",
  "input_revision": 3,
  "status": "succeeded",
  "image_path": "assets/generated/j001/result.png",
  "sha256": "<由系统计算>",
  "width": 1536,
  "height": 1024,
  "asset_refs": ["character:hero:v3"]
}
```

以实际生图结果路径为来源，再复制到任务目录并验证文件。`--output-last-message/-o` 保存最终消息，不应误作图片保存参数。未知的模型、seed、尺寸控制与流式预览能力不写成保证支持。

## 7. 资产、按话隔离和边出边改

全局资产库保存角色/服装/道具/场景/风格的 ID、版本、原图与 hash；每话固定资产版本。缓存用于本地去重和请求组装，不保证跨 Codex 会话免于再次提交图片内容。

```text
series/
  assets/
  episodes/ep-001/
    episode.json
    storyboard.json
    asset-lock.json
    pages/<page-id>.pcraft
    jobs/<job-id>/{request.json,events.jsonl,result.json}
    assets/generated/
    exports/
```

人工操作的当前页面与后台生成目标要按 ID 分开。下一话开始制作时不抢焦点，上一话保留人工可编辑视图。

逐格完成即回填即可实现边出边改；不以持续中间预览为第一版前提。拖图/裁切/改框可保留到新候选回填；修改提示词、人物资产或构图则提高输入修订号，旧结果保存为过期候选，不静默覆盖。

本话生成完即可触发下一话，QA 是独立状态。失败格子需标记本话部分完成；导出绑定到已通过 QA 的确切文档修订，重生图或修改后相应 QA 状态失效。
