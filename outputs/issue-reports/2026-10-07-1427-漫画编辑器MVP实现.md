# 漫画编辑器 MVP 实现报告

## 1. 基本信息

- 日期：2026-10-07（Asia/Shanghai）
- 状态：部分解决
- 影响范围：当前仓库新增漫画编辑器前端、Codex CLI 接入层和本地桥接服务；尚未接入 PhotoCraft 原生文档命令，也未执行真实生图。

## 2. 问题或任务概述

用户明确要求主格、副格、气泡、底图和渐变拆开，均可独立调整；Codex 负责排版和生图，程序负责显示结果、任务排队和人工操作，并按话和页面管理。

## 3. 最终结论

已完成一个可运行的 MVP 基线：五类对象以独立图层存在，支持画布选择、拖动、四角缩放、属性编辑、分话/分页、项目 JSON/PNG 导出；Codex 排版与生图已有本地 API 和 worker，可通过 imagegen、参考资产图路径和 JSONL 事件接入。真实 Codex 生图回写和 PhotoCraft 页面同步仍是后续工作。

## 4. 发现与排查路径

- 检查仓库时只有 README 和历史报告，没有可运行编辑器或服务。
- 根据需求选择无依赖 HTML/CSS/JS SVG 编辑器，避免先引入构建链，优先验证对象模型和人机操作。
- 根据已确认的 Codex CLI 能力，排版和生图拆成 layout、image 两种任务；生图只接受明确的 saved_path 事件，不把自然语言当作图片路径。
- 用本地 HTTP 桥接服务将浏览器任务转交给 Python worker，浏览器负责显示和人工调整。

## 5. 根本原因

- 已确认事实：PhotoCraft 本身不是漫画语义层，也不提供完整漫画项目、分话和 Codex 任务队列；这些能力必须由上层程序提供。
- 已确认事实：Codex CLI 可以作为排版与生图 worker，但需要结构化 JSON、参考图路径、事件记录和结果文件管理。
- 合理推断：先用独立对象模型和 SVG 画布验证交互，可以降低后续替换为 PhotoCraft 命令或原生文档的成本。
- 尚未验证假设：PhotoCraft 原生页面和 Smart Object 回写的最终命令映射、不同 Codex CLI 版本对 saved_path 的一致性。

## 6. 处理方案

采用三层结构：

1. app/：浏览器编辑器，独立渲染主格、副格、底图、渐变和气泡；负责选择、拖动、缩放、属性编辑、按话/页面组织、保存和导出。
2. services/codex_worker.py：标准库 worker，把排版和生图分开调用 codex exec --json --skip-git-repo-check，生图自动加 imagegen，资产图通过重复 -i 传入，输出 JSONL、结果摘要、复制后的资产和 SHA-256。
3. services/server.py：绑定 127.0.0.1 的本地 HTTP 服务，提供编辑器静态文件、项目和资产持久化、任务队列、取消、生成产物访问及 revision 元数据。

## 7. 实际变更

- app/index.html：编辑器布局、画布、图层树、属性面板、Codex 队列。
- app/styles.css：深色编辑器界面、面板、焦点和响应式规则。
- app/app.js：五类独立对象、拖动、四角缩放、属性编辑、气泡文字、资产路径、按话/页面、保存、PNG/JSON 导出、Codex API 队列和 revision 冲突保护。
- services/schema.json：episode/page/panel/asset/layout/job 结构。
- services/codex_worker.py：Codex CLI 任务执行、重试、事件、saved_path、资产复制和哈希。
- services/server.py：本地浏览器与 worker 桥接。
- services/README.md、根目录 README.md：启动和调用说明。
- design-system/codex-comic-studio/MASTER.md：编辑器设计系统。
- .gitignore：忽略本地工具目录和 Python 缓存。

## 9. 残余风险与未解决事项

- 当前画布使用 SVG 负责可编辑构图，底图资产会在对应主格/副格内裁切显示；尚未写回 PhotoCraft 文档。
- Codex layout 和 image 的结构化结果已能由服务端组合并返回，真实 Codex CLI 的生成目录、图片回写和长任务取消仍需实机验证。
- 真实生图的 saved_path、生成目录和长任务取消行为需要在本机实际 Codex 运行中再验证。
- 大尺寸长条漫画、复杂文字排版、CJK 字体和多页性能尚未验证。

## 10. 回滚或恢复方法

- 删除 app/、services/ 和 design-system/ 即可回退到此前的项目启动基线。
- 本地桥接服务不写系统配置；停止运行中的 python services/server.py 即可恢复。
- .data/ 和 work/ 为本地运行数据/工具目录，均已从 Git 排除。
